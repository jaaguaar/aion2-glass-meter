# Дослідження: власний DPS-метр для Aion 2

Дата: 2026-11-19. Стек: C# / .NET, без Npcap, лише вбудовані засоби Windows.

## Висновки коротко

1. **Пасивний метр можливий.** Бойовий трафік Aion 2 іде по TCP, **не зашифрований**, частина пакетів стиснута **LZ4**. Ключів і хендшейку немає, тож метр можна запустити посеред сесії.
2. **Npcap не обов'язковий.** Усі відкриті метри використовують Npcap/libpcap. Технічно нам потрібен лише TCP-потік з одного порту. Це дає raw socket (`SIO_RCVALL`) або Pktmon/ETW, обидва потребують прав адміністратора. Перевірити першим кроком прототипу.
3. **Офіційний метр у грі вже є** (патч 2026-04-01, `Ctrl+X`): лише особистий урон, режим деталізації по скілах. Урону групи, імовірно, не показує (джерела розходяться), експорту немає.
4. **Дані персонажів** беруться з недокументованих JSON-ендпоінтів сайту plaync. Офіційного API немає, офіційні рейтинги прибрали у 2026.
5. **Ризик:** офіційного дозволу чи заборони метрів немає. NCSoft (стрім 2026-05-26) жорстко виступила проти **збору й публікації** чужих DPS-даних на сайтах-рейтингах і пообіцяла заблокувати це в грі. Особистий локальний метр без вивантаження даних — найбезпечніший варіант, але гарантій нема.

## Протокол (за кодом A2Tools; framing перевірено вручну)

**Транспорт**
- TCP. Порт визначається під час роботи за «бойовою сигнатурою» в даних. У коментарях трапляються порти 54141 і 13328.
- З того ж порту сервер тримає ще й TLS-з'єднання. TLS-записи (`17 03 03 <u16 len>`) треба пропускати, інакше парсер збивається.
- Перехід на інший сервер позначається в потоці маркером `16 36`.

**Фреймінг**
```
00 ...                                 padding
17 03 03 <u16 len> ...                 TLS-запис, пропустити
<varint len> <payload>                 пакет; len = payload + 4
<varint len> FF FF <u32 LE size> <lz4> LZ4-бандл (вкладені пакети, до 4 рівнів)
```
- Varint: 7 біт + біт продовження.
- Payload починається з 2-байтового опкоду. Другий байт зазвичай `36`/`37`/`38`/`8D`/`FF`.
- Максимальний розмір пакета 65535. При «сміттєвій» довжині — ресинхронізація по одному байту.

**Опкоди**

| Опкод | Значення |
|---|---|
| `04 38` | Урон / удар |
| `05 38` | DoT / HoT |
| `40/41 36` | Спавн мобів |
| `44/45 36` | Спавн гравців |
| `42 36` | Смерть |
| `02 97` | Склад групи |
| `1B 92` | HP/MP |

Опкоди зміщувалися після патчу в червні 2026, тож вони **змінюються з патчами**. Таблицю опкодів робимо конфігурованою.

**`04 38` — урон**
1. Target ID — varint.
2. Switch — varint. `switch & 0x0F` дає тип удару: 4–7 означають урон, 0 і 2 — промах чи опір. Біт `0x02` означає, що далі є прапорці.
3. Невідомий varint.
4. Actor ID — varint.
5. Skill ID — u32 LE.
6. 1 байт пропуску.
7. Тип урону — varint, де 3 означає крит.
8. Прапорці (опційно): спина/фронт, perfect `0x04`, double `0x08`, блок, парирування.
9. Два varint; другий — це урон.
10. Кількість мульти-хітів 0–25, далі значення кожного хіта.
11. Опційний heal-суфікс `03 00 <varint>`.

**`05 38` — DoT/HoT**
1. Target ID.
2. Байт ефекту: `02`/`0A`/`06`/`0E` означають урон, `01`/`09`/`0B` — хіл.
3. Actor ID.
4. Невідомий varint.
5. Skill ID (u32 LE ÷ 100).
6. Сума.

Нікнеймів у пакетах урону немає. Імена приходять у спавн-пакетах, тобто при телепорті чи вході в данж.

## Дані персонажів (plaync, неофіційно)

- Сторінка пошуку: <https://aion2.plaync.com/en-us/characters/index>
- Пошук: `https://api-search.plaync.com/aion2global/search/v2/character`
- Профіль (рівень, клас, бойова сила, рівень предметів, статистика): `https://aion2.plaync.com/api/character/info`
- Спорядження: `https://aion2.plaync.com/api/character/equipment`
- Параметри: `region` (наприклад, `nae`), `lang=en-US`, `serverId`, `characterId`.
- Авторизація не потрібна. Через CORS із браузера не працює, але для десктопного C#-застосунку це не проблема.
- Регіони: Global (NAE, NAW, EU, SA, Asia) і TW. KR-ендпоінти повертають 404 із не-корейських IP.
- Сервер обмежує частоту запитів (Retry-After). Робимо кеш і не більше кількох запитів на секунду. Формат може змінитися без попередження.
- Приклади використання: [nklsgod/AION-2-Character-Check](https://github.com/nklsgod/AION-2-Character-Check), Go-клієнт [nuriland/aion2-api](https://pkg.go.dev/github.com/nuriland/aion2-api).

## Правила для нашого метра (мінімізація ризику)

- Тільки пасивне читання трафіку. Жодних ін'єкцій, читання пам'яті чи змін пакетів.
- Оверлей — окреме прозоре вікно з наскрізними кліками. Гра в режимі borderless.
- Нічого не вивантажуємо: дані бою лишаються локально. Ніяких публічних рейтингів чужого DPS (саме проти цього виступила NCSoft).
- Запити до plaync — рідко і з кешем.

## Наступні кроки

1. **Spike захоплення:** .NET-консоль з raw socket `SIO_RCVALL`, що бачить TCP-потік гри в обидва боки. Якщо вхідних чи вихідних пакетів бракує — переходимо на Pktmon/ETW.
2. Реассемблінг TCP-потоку, фреймінг, LZ4 (NuGet `K4os.Compression.LZ4`), лог опкодів у файл.
3. Парсер `04 38` / `05 38`, звірка з офіційним метром (`Ctrl+X`) на опудалі.
4. WPF-оверлей: DPS, урон по скілах, учасники групи.
5. Підтягування профілю й спорядження з plaync для порівняння білдів.
